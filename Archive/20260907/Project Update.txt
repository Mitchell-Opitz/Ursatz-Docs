Notable per-subtype constraints: Retrograde requires an explicit non-zero bitmask of which dimension(s) reverse, no silent "reverse everything" default; Augmentation/Diminution require an explicit dimension enum (durations/inter-onset/structural/notation/performance timing) with DURATIONS as enum value 0 so an uninitialized caller variable can never silently touch performance timing; Fragmentation/Expansion/Contraction share one array-of-EntityID-references-plus-count shape (extract/append/drop by reference, never by copying NoteEvent payloads); RetrogradeInversion composes Retrograde+Inversion rather than reimplementing either; Ornamentation is the one subtype the Registry explicitly calls out as needing Provenance most, since its one-to-many fan-out (one source event to several derived events) is the trickiest case to get right — though every subtype carries provenance via the base contract regardless

IntervalAnalysis, ScaleAnalysis, ChordIdentification, KeyEstimation, VoiceLeadingAnalysis, CadenceDetection, MotifDetection, PhraseSegmentation — every one follows the same "caller supplies the already-measured dimension, the analyzer packages it" division, since PitchIdentity carries no tuning-system semantics at this layer and none of the eight can derive their own measurements from raw pitch tokens. GenerationRecord (Entity) — the durable, standalone log entry that a generation run happened (seed, generator_version, framework_version, configuration, provenance), distinct from CandidateSet's reproducibility bundle (scoped to one generate() call) and Generator's own version field (a declared capability, present whether or not it was ever invoked)
